# Systematic full-text access: practical request routes

Checked against official sources on 7 October 2026. These are access routes to pursue when needed; no accounts were created, licensing requests sent, contracts accepted or fees incurred. Stanford's negotiated terms and the requested analysis environment still need confirmation from the library. A successful browser login, API account or Scopus query does not establish full-text mining entitlement.

Ordinary institutional browser access subsequently delivered **15 original APA PDFs**. APA then displayed an explicit hourly full-text limit and a security-verification page, and automated APA downloads stopped. **No institutional-email download links were requested**, so no resulting emails should be expected. Direct browser and independent repository copies resolved papers that earlier automated routes could not retrieve. This does not establish a publisher-wide subscription failure.

For an individual paper, APA's [access instructions](https://www.apa.org/pubs/databases/access/) describe **Get Access** and an institutional-email option for a single-use PDF link when the institution has the relevant entitlement. That is a delivery option, not an API credential. It was unnecessary for the direct downloads and was not used to work around the later security gate. Resume publisher downloads only when the publisher permits them; complete any offered human verification yourself. Stanford's [VPN instructions](https://uit.stanford.edu/service/vpn/mac_secureclient) describe the full-traffic profile for restricted library resources.

Before replacement sampling, the 240-paper missing-text queue contained 62 APA papers, 76 on Sage (including AERA and marketing titles), 38 Oxford, 24 Chicago, 17 INFORMS, 11 AEA, 9 Academy of Management and 3 Duke papers. These historical counts precede replacement sampling; they are not subscription-denial counts. For current counts see the [replacement results](replacement_report.md) and [remaining DOI queue](manual_downloads.csv).

## Start with Stanford and APA

1. Open Stanford's [Psychology library page](https://library.stanford.edu/psychology), choose **PsycArticles**, and authenticate through the library's listed access link. Check one missing DOI in that browser. The page lists psychology librarian Regina Lee Roberts, **regirob@stanford.edu**. Ask which platform Stanford licenses for the relevant journals and years; this investigation did not verify that it is EBSCO rather than APA PsycNet or another provider. PsycArticles supplies full text; PsycInfo supplies bibliographic indexing and abstracts. [APA's database FAQ](https://www.apa.org/support/psycarticles.html) explains the distinction and distribution platforms.

2. Ask Stanford to confirm the existing licensed route and arrange any missing project access, using **library-data-services@lists.stanford.edu**. Its [Data support and services page](https://library.stanford.edu/research-support/data-support-and-services) explicitly covers project-specific data acquisition, vendor negotiations, contracts and provisioning local or remote access. Include Regina and/or **contact-cidr@stanford.edu** for the subject and technical sides. [Stanford's TDM service](https://library.stanford.edu/text-and-data-mining) lists the CIDR contact. Send the DOI list, study dates, research purpose and the requested delivery/analysis arrangement below.

3. **Check existing entitlement first.** If Stanford’s approved Workbench already includes the requested articles and permits the planned processing, use that arrangement. If the titles, years, local retention or analysis environment are not covered, have Stanford ask APA/ProQuest for **project-specific full-text TDM access** or additional permission. Start at [Contact APA Databases](https://www.apa.org/pubs/databases/contact) for licensing and technical support. If APA directs you to a permissions request, use the [APA permission request form](https://input.apa.org/f/permissions-request-form), which routes to **permissions@apa.org**; the [APA instructions](https://www.apa.org/about/contact/copyright/seek-permission) describe this route for requests outside the ordinary article permissions workflow. Ask whether APA can supply an approved corpus, institutional API access or a ProQuest Workbench arrangement. I found no official, documented self-service APA full-text API-key signup. That does not establish that a negotiated API or corpus service is unavailable.

A request for additional coverage has a concrete precedent: a [ProQuest case study](https://about.proquest.com/globalassets/proquest/files/pdf-files/case-studies/misreported-research-in-psychology--a-text-and-data-mining-project_web2.pdf) describes a Berkeley researcher obtaining special pilot permission from the library and APA for six psychology journals through TDM Studio, including JPSP and Journal of Applied Psychology. It does not establish Stanford entitlement to the same corpus or mean every already-covered Workbench project needs a new APA permission request.

## ProQuest TDM Studio account and corpus

1. Open [Create Account](https://tdmstudio.proquest.com/createaccount). Use the Stanford institutional email address, create a password, enter the short project description and complete the email verification. The indexed official form specifies these steps and a 150-character project description; registration does not itself confirm institutional activation. Institutional recognition and Workbench access remain separate checks; use Stanford's library contact above if the account does not expose the needed Workbench.
2. Sign in at [TDM Studio](https://tdmstudio.proquest.com/home). Ask **TDMStudio@clarivate.com** and Stanford to confirm that the APA journals, years and document types are eligible in this particular institutional Workbench. Stanford currently lists TDM Studio among its [research collections](https://gsbresearchhub.stanford.edu/services/library-research-collections). This confirms that Stanford lists the resource, but not this researcher’s Workbench access, subscription tier or coverage of every PsycArticles title.
3. After activation, choose **Create New Dataset**, select eligible publication titles and date/document filters, then open the Jupyter Notebook environment. The [official quick-start guide](https://about.proquest.com/globalassets/proquest/files/toolkits/tdm-quick-guide-2022-nov.pdf) documents Create Account, dataset creation, the Open Jupyter Notebook button, Python/R use and the support address. Match the retrieved records to the project DOI list; title/year filters alone do not identify the sampled papers.
4. Confirm the approved place for analysis and what may leave it. The [current supplemental terms](https://about.proquest.com/en/about/supplemental-terms-of-use-tdm-studio/) authorize analysis of eligible content in the designated Workbench and export of permitted derived data. They do **not** establish a general right to export all raw PDFs into the local Literature folder. Ask separately for approved local full-text delivery and retention when needed for the Literature folder. Also identify the intended external LLM service and ask whether content may be sent to it; permission to analyze inside Workbench does not establish that right. The terms separately restrict export of models developed or trained on publisher content, which is different from permission to export the source text.

The [current ProQuest factsheet](https://pq-static-content.proquest.com/collateral/media2/documents/brochure-tdmstudio.pdf) also describes an Analytics Assistant for custom prompt-based annotation. It is included at no additional cost with the **unlimited subscription**; Stanford’s tier has not been verified. This could offer an approved in-platform analysis option if local processing is unavailable. It does not supply local PDFs or reproduce our session-agent screening evaluation: a different model and analysis environment would need separate documentation and evaluation.

## EBSCO route, if Stanford's licensed platform supports it

1. Ask Stanford's electronic-resources administrator whether its EBSCO Discovery Service account is eligible and enabled for **EDS API** use with the relevant PsycArticles database. The [official prerequisites](https://developer.ebsco.com/eds-api/docs/introduction) require an institutional EDS customer account, API activation through the EBSCO representative, and an API profile configured in EBSCOadmin. A personal developer-portal registration does not supply those entitlements.
2. Have the administrator provide the approved **API username/password, API profile and EBSCO Customer ID**, or the supported institutional IP-authentication setup. [EBSCO Support](https://connect.ebsco.com/) is the documented assistance route. Confirm systematic full-text and AI use under the relevant APA/EBSCO institutional license; EDS discovery access alone is not that confirmation.
3. With approved credentials, the [request sequence](https://developer.ebsco.com/eds-api/docs/making-your-first-request) is authenticate, create session, search, retrieve the record using its database ID and accession number, then end the session. [Full-text documentation](https://developer.ebsco.com/eds-api/docs/working-with-full-text) distinguishes actual HTML/PDF delivery from external links. PDF links can expire and require a fresh Retrieve request. This route can only deliver content enabled in the profile and available for that record. A returned citation, abstract or PsycInfo table of contents is not a retrieved main article.

Scopus is a separate metadata service. Elsevier's [Article Retrieval documentation](https://dev.elsevier.com/tecdoc_text_mining.html) distinguishes entitled full text from metadata-only responses: an unentitled default request can return an abstract, while an explicit FULL request returns an error. Finding a DOI in Scopus does not establish full-text entitlement. An existing Scopus key therefore does not unlock APA, Sage or Oxford full texts.

## Suggested request text

> We are conducting a Stanford research project identifying studies in which author teams collected or commissioned quantitative human participant data. Our stratified pilot contains 620 articles from 62 journals, one per year from 2016–2025; the attached DOI list identifies the requested articles on your platform. We need main texts and associated methods/supplements for research verification, with private storage where permitted. Our planned analysis includes computational extraction and LLM-based methods classification, followed by research-team checking; we are not requesting public redistribution of the corpus. Please confirm Stanford's existing entitlement and the approved route: institutional API credentials, a securely delivered corpus, or a designated TDM Workbench. Please specify permitted local retention, the approved analysis environment and export of labels/short evidence extracts, request limits and any fees before activation. If local full-text storage is unavailable, please identify an arrangement that permits the verification analysis within your environment.

The paragraph is a draft for the researcher/library to adapt. Nothing has been sent, and no publisher has approved this project through these routes yet.
